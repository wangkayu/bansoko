## 新增

- 种子搜索新增 Nyaa 来源，可在连接设置中单独管理其访问方式。
- 检查更新时显示新版本的更新说明。
- 一次性下载可单独选择未识别集数的文件是跳过还是按「未知内容」整理。
- 一次性下载的设置步骤可逐个种子勾选要下载的文件，包括子文件夹里的视频和字幕；同一集选了多份时按全局冲突策略处理。
- 执行记录显示种子信息：列表中有字幕组、主要标签、版本、大小和种子标题，替换旧版本的记录带「替换版本」标记；详情中可查看来源站点、发布时间、info hash（可复制）和全部标签。
- 订阅开始前也能按字幕组设置集数偏移：草稿和未开始的订阅在 RSS 页的每个字幕组上都可调整，试运行立即按新集数重算；偏移对话框显示换算示例，例如「第 53 集 → 第 5 集」。
- 编辑番剧标题时（包括一次性下载的设置步骤），TMDB、BGM 的中文名与原名和来源标题显示为候选，点击即可填入；匹配 TMDB 时可勾选同时把标题改为匹配到的名称。
- 缺少 TMDB/BGM 匹配或模板用到的变量不存在时，下载完成的文件进入「等待配置」：文件留在下载目录，补全设置后自动继续入库，不计为失败。

## 改进

- 连接设置中可直接添加 RSS 访问；内置连接只能编辑。
- 代理与下载器对话框在提交前校验输入，布局与文案更清晰。
- 字幕组「必选」不再占用自动选择名额，组分最高为 100。
- 番剧配置标题区绑定 TMDB 电影时显示 Movie，并链接到电影页面。
- 海报墙铺满窗口宽度，窗口越宽，浏览页每行显示的番剧越多。
- 同集多版本的默认排序中，「reltitle 字幕语言」改为简日繁日双语优先，其次是简日。升级只更新全局设置中未改动过的这一项；已添加的订阅保持原有设置，如需新排序请在该订阅中修改。
- 浏览页和搜索中点击已订阅的番剧会打开已有订阅，不再新建草稿；需要第二个订阅时，在订阅卡片上使用「复制为新订阅」。
- 番剧的「类型」（剧集/电影）改为独立设置：首次匹配 TMDB 时预填一次，之后更换或清除匹配都不会改变它。
- 修改订阅的标题、季度、年份或 TMDB/BGM 匹配后，已入库的文件也按新设置重新命名，与修改命名模板时相同；缺少匹配或模板用到的变量不存在时，文件留在原处并在文件列表中显示原因。
- 修改字幕组集数偏移后，已入库的文件换到新集数：同一集的文件按同集多版本的保留方式比较，留下优先的一份，其余删除；都保留时按冲突策略处理，结果记录在订阅动态中。偏移对话框说明这些影响。
- 对齐文件时，目标位置已有同一订阅同一集的文件，先按同集多版本的保留方式比较，再移动保留的文件；其他情况按冲突策略处理。
- 下载期间修改了订阅设置的文件，入库后自动移到按当前设置生成的位置，不受「自动对齐」开关影响。
- 修改标题、绑定、季度、年份、类型或命名规则后，订阅的文件会按当前设置重新检查；开启「自动对齐」时移到新位置，不会重新下载。
- 保存元数据时，未提交的资源会在同一次保存中重新评估，不再需要单独的重新评估。
- 浏览页的季度下拉固定为往后两季到往前两年，本季始终可以直接选到；更早的季度用箭头翻页，或用搜索查找作品。
- 取消选择字幕组时，该组在订阅中尚未完成的下载随之取消，并在 qBittorrent 中连同已下载的数据一起删除，同一集改由其他字幕组的资源下载；已完成下载或正在入库的不受影响，也不发送失败通知。
- 重新选择字幕组后，之前因未选择而跳过的资源立即重新评估，不必等待 RSS 刷新或新资源出现；订阅停止期间重新选择的，在恢复订阅时重新评估。
- 执行记录中可取消尚未入库的下载（也可通过 API、MCP 和命令行取消），记录显示「已取消」；订阅中的资源可用「重试」重新下载，一次性下载取消后不能重试。

## 修复

- 已有下载和入库记录时，升级不再因数据库迁移冲突而失败并回滚。
- 文件名带 JPSC、JPTC 标记的字幕现在能识别语言，简日与繁日字幕不再因同名只保留一个。
- 展开种子查看文件列表时，torrent 现在走该来源连接配置的代理，不再直连。
- 带 AniBT 编码、位深等标签的种子入库后不再卡在收尾；文件已复制却一直显示「入库 进行中」的记录，升级后会自动完成。
- 手机上用下拉选择季度后不再跳回本季度；在设置等页面切换栏目时保留所选季度。
- 新订阅多个来源同时刷新时，同一集不再重复下载：同一订阅的候选先进入「等待比较」，统一比较后只下载一份。
- 冲突策略为「跳过」或「加版本号」时，洗版换到同一路径的新版本不再因目标已存在而入库失败；活动记录在受理时显示「将替换」，入库完成后才显示「已替换」。
- 媒体库文件正被播放器等占用时，洗版删除旧版本和覆盖入库会每 5 分钟自动重试，最长 24 小时；仍失败时写入活动记录并发送通知，不再让部署恢复卡住，也不再一律提示「没有权限写入目标位置」。
- 清除 TMDB 匹配时，一并清空由它预填的季度、年份和总集数；更换匹配时改用新匹配的值，不再沿用第一次匹配的结果。
- 海报因服务重启或网络波动加载失败后会自动重试，窗口回到前台或网络恢复时立即重试，不再需要刷新页面。
- 下载和入库进展时，订阅列表的入库进度和状态会自动更新，不再需要手动刷新。
- 下载过程中修改 TMDB 季度后，同一集不再被当作新的一集再下载一份：集数识别只看订阅和集号，季度只用于命名。
- 顶栏状态中的「下次自动任务」时间到点后会自动更新，打开状态面板时也会重新读取，不再一直显示已过去的时间。
- 编辑标题时，候选标题不再遮住输入框的选中边框。
- 模板变量列表中示例很长的变量（如 InfoHash、文件名）在条目内换行，不再把一次性下载设置等窄栏撑出窗口。
- 一次性下载整季合集（如 24 集加附带文件）提交时不再报内部错误；包含数百个文件的合集同样可以下载。文件过多、无法记录的种子会提示「种子包含的文件过多，无法下载」，订阅中的这类种子标记为同样的原因。
- 包含 128 个以上文件的种子下载完成后，不再在校验文件阶段失败，合集里的视频都能入库。
- 校验文件只核对每个文件的大小和位置，不再读取整个文件，大体积合集的校验时间不再随体积增长。
- 合集中每个视频单独读取分辨率、编码等媒体信息，排在后面的视频不再因共用的时间上限缺少这些信息。
- 字幕后缀模板留空时，带字幕的资源不再在入库整理阶段失败。
- 一次性下载在文件校验完成、等待整理时不再被错误收尾；已经因此卡在「进行中」的记录，升级后会自动继续整理和入库。

## 注意

- 目前只支持一个下载器，下载目录改为必填。
- 升级时，如果同一订阅里已有属于不同季的文件，只保留当前季的文件参与替换版本；其他季的文件留在原处，并在订阅动态中记录数量，可按需手动清理。
- 订阅已有入库文件，或有未完成的下载、入库时，不能在剧集和电影之间切换类型。
- API 与 MCP 中番剧元数据的类型字段改名为 media_kind；调用它的脚本或助手需改用新字段名。
- API 中一次性下载和下载任务的 target_facts 不再逐个列出目标，改为给出目标数量 target_count；升级时已有记录一并改写。
- API 中文件的指纹改为 metadata 形式（文件大小，以及可取得时的设备号与 inode），不再是 sha256 内容摘要；升级时已有记录一并改写。
