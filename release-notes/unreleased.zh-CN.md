## 新增

- 一次性下载可选择「仅下载所选文件」，只下载选中的视频及其字幕。默认关闭，不改变入库范围。

- 默认规则可设置新订阅的首选标题，默认不修改。首次匹配齐全时，若所选来源没有该标题，则保留当前标题；已有订阅不受影响。
- 节目配置、一次性下载和文件管理可从已有的 TMDB 或 Bangumi 绑定直接查看分集，无需重新匹配。

- AniBT、Mikan 和自定义目录新增「列表」，支持按标题、状态、播出形式和可用性筛选，可查看简介、浏览种子和批量订阅。简介中的海报可以点击放大。

- Telegram 通知模板可在正文中用 button(target, label) 添加跳转按钮。按钮在消息下方逐行显示，不影响飞书或 Webhook 正文。

- 种子检索（Jackett）结果第二行显示站点分类、做种与下载计数以及计费标签（免费、折扣百分比、上传倍率）；分类名称取自单站 caps，读取失败时省略且不影响检索，下载数为 0 与标准计费（1/1）不显示。

- 下载、入库及未识别文件通知支持 task.origin，区分订阅（subscription）与一次性任务（one_shot）。来源相关事件新增 release.site 与 release.link，分别表示发布站点和明确的发布详情页；下载地址仍使用 download.link。
- 容器内可通过 bansoko-server update check|apply|status 检查、受理和查询内嵌更新，支持人读及 JSON 输出；仅限 root 或服务 PUID，不需要 Web 会话或 API token。
- 入库完成和执行失败通知支持原始文件名解析属性 frt.*；文件被替换通知可分别使用 frt.* 和 taker.frt.* 展示新旧文件属性。
- 在编辑通知渠道的「触发事件」旁可为入库完成、下载已提交或入库失败绑定本地脚本。绑定独立于通知渠道；手机可按文件名筛选和翻页。脚本启动后，对应执行记录会显示触发标记；开启「记录脚本结果」后，可查看脚本回传的摘要和可选 HTTP 状态。重试只显示本轮结果。脚本缺失会在事件中告警。
- 容器镜像内置 curl 和 jq，事件脚本可发送 HTTP 请求并读取事件 JSON。Python 不随镜像提供。

## 改进

- 「未识别集数的文件」移到「订阅策略 → 默认规则」，已有设置和处理方式不变。

- 目录列表可点击节目标题打开配置，保存或订阅后原地更新列表。手机端把原名放在标题旁，简介、浏览和快速订阅按钮不再单独占一行。
- 手机端「已订阅」页把状态筛选、标题筛选和管理入口放在同一行，点击筛选图标才展开输入框。
- 窄屏上的「发现」页会收起上一季和下一季箭头，保留季度下拉框，让四个操作按钮尽量与它同排。

- 桌面顶栏的服务状态改为波形图标加状态点，点击后查看各项连接状态和需要检查的原因。

- 浏览与搜索海报卡的「已订阅」和「已结束」改用更紧凑的小圆角标签。有星期或评分时，角标固定在第二行；没有时放在第一行。

- 下载器入口和弹窗统一使用下载图标，传输速率仅用方向箭头，不再重复显示图标。

- 日志窗口将业务事件与程序日志分开。程序日志可跨重启搜索；从一条警告点「查看此任务」，即可查看保留期内同一任务的前后记录。日志按 UTC 日期或每卷 10 MiB 轮换，总量约 30 MiB，最长保留 7 天；磁盘不可用时显示最近的内存记录。
- 系统默认通知按评审稿调整：开始订阅不再在正文重复作品名，仅开始订阅附可用的作品资料链接；发现新发布显示来源站点、按来源显示标签并链接安全的发布详情页；下载失败先显示原因，再显示发布标题及可用的详情页链接；加入下载通知保持简洁且不附作品资料链接。加入下载和入库完成通知统一使用「字幕组／Group」，不再称「原文件字幕组」。已替换旧版本继续按新旧版本列出发布标题、字幕组和入库前原始文件名。已有自定义模板与已冻结通知不变。

- 种子结构改为文件名与大小分行显示，不再依赖等宽字体对齐；长名称和特殊字符不会打乱条目布局。
- 入库通知的系统默认模板增加原文件字幕组；文件被替换通知分别展示新旧文件的字幕组与规格。缺值行自动隐藏，中英文同步。
- 测试投递的标题统一带 [TEST] 标识；正文和业务通知不受影响。
- 入库完成通知的 out.name 改为实际落盘文件名，out.dir 和 out.path 改为应用运行环境中的绝对父目录与绝对路径；系统默认模板不再显示目录行，自定义模板仍可引用这些变量。out.subtitles 改为已绑定并成功入库的字幕最终文件名列表，不含目录，按处理顺序逐行显示，为空时整行隐藏。
- 通知模板编辑页改为卡片布局：事件列表与编辑区各自成卡，系统默认模板以带标签的只读面板展示，自定义模板事件改用强调徽章。
- 洗版属性比较统一使用发布标题的 reltitle 解析结果、AniBT 采集标签及来源组评分；新增 reltitle 版本号比较项。全部比较项相同时保留现有文件，不再按发布大小决胜。
- 命名模板新增 segment(value, prefix, suffix) 与 joinNonEmpty(values, separator)，便于组合可选片段；空字符串可跳过，0、false、空格和纯符号按原值保留，未准备的执行事实仍保持待准备状态。发布语言字段改为 reltitle 结果的纯派生，原始文件名解析只使用冻结的文件证据。
- 下载前尚未取得的文件与媒体事实现在明确标为待准备，不再生成占位目标路径；其余已确定目标仍可正常进入下载与后续入库。

## 修复

- 只有实际替换旧版时，日志才显示「已替换旧版本」。展开事件可查看保留版和被替换版；由媒体库核对触发的替换会注明来源。
- 自动化运行记录和日志区分已完成的目录检查与排队工作；部分任务失败时，仍会显示已确认的结果。
- 自动化运行中断且无法确认结果时，设置和日志显示「结果未确认」，不再标为失败。
- 更新准备失败时，程序日志区分网络、更新包校验和本地存储等原因，不记录请求地址或文件路径。
- 滚动日志窗口中的事件或日志列表时，页签和筛选栏保持可见。
- AniBT 和 Mikan 订阅的入库完成、入库失败通知优先使用来源站封面。从这两个站点的目录发起一次性下载时，下载和入库通知也优先使用对应目录封面；无可用来源封面时，依次使用 Bangumi、TMDB 或占位图。
- 升级前已入库的文件在扫描和文件匹配时恢复读取其历史发布证据，不再因缺少新版快照字段而误报「命名模板缺少所需信息」。
- 搜索一次性任务的命名组事实不再把内部检索标识（search-query:…）渲染进预览路径；预览与实际入库一致，anime.group 均为空。
- 文件原始解析属性随受管文件保留，操作详情清理后仍可用于新旧版本对照。
- 通知渠道等表单中的密码输入框（Bot Token、Webhook 地址、签名密钥等）丢失统一高度与字号，已修复并与其他输入框对齐。

## 注意

- 升级到 0.2 时，请拉取新镜像并重建应用容器。仅在应用内更新不会安装 curl 和 jq。在旧容器上，引用这些命令的脚本即使通过权限检查，也可能因找不到命令而显示「执行失败」。
- 搜索一次性任务不再从发布标题解析组名，也不再使用 unknown 占位：${group}（anime.group）对搜索一次性的预览与入库均渲染为空。需要标题中的字幕组名时使用 ${rt.group}（发布标题解析）或 ${frt.group}（文件名解析）；订阅与自定义来源的组名不变。
- 文件命名的 media.resolution 只来自实际文件探测，不再从发布标题、原始文件名或受理时的 media.quality 回填；未探测到值时保持为空。媒体与文件事实不参与洗版资源优劣比较。
- 新通知的 release.src 统一为获取渠道 anibt、mikan、nyaa、jackett 或 custom，不再输出 provider_group/custom_rss。使用旧值判断的自定义模板需自行调整；不会自动给自定义模板加来源行。
- 来源在任务受理或事件创建时保存，延迟生成和重投不重新查询当前来源。缺少站点或详情页证据时保持为空；含凭据或无法安全解析的链接不外发，详情页不会用下载地址代替。
- 本次不兼容旧任务输入、旧检索快照摘要及旧请求的重放协议，也不回填历史来源；升级前应完成在途任务，升级后重新检索并发起新请求。已冻结通知内容不改写，不保证历史待处理通知可继续重放。
- 旧 chain 模板函数与 ep.kind 标题分类已退役。升级只自动转换与旧内置默认完全相同的全局洗版配置；自定义或订阅级旧洗版配置，以及仍引用 chain、ep.kind、旧语言/分辨率来源或受影响 ${res}/media.resolution 的当前配置和历史重放输入，会明确阻止升级。请先备份并人工核对这些配置，不会静默清空订阅偏好或改写历史摘要。
- 本地更新命令仅在新版服务端提供；旧镜像或旧 overlay 不会自动获得该能力，首次升级仍使用 WebUI 或切换镜像。WebUI 升级后 /app/bansoko-server 可能仍是旧 base；应读取 BANSOKO_UPDATES_ROOT 下的 current 文件，用它指向的 releases 目录中的 bansoko-server 调用命令，没有 overlay 时使用 /app/bansoko-server。update help 提供完整容器调用示例，不依赖 /proc/1/exe 权限，也不增加 Docker 管理 socket。apply 默认只表示已受理；--wait 仅在命令进程存活时等待重连，handoff 可能终止 docker exec。断连或 Docker 返回码不代表更新成败，重启后须用新的 exec 查询 update status。
- 已选择“系统默认”的通知目标会采用新版文案，自定义模板不变。
- frt.* 仅支持命名、入库完成、执行失败和文件被替换场景；其他事件中原有的 frt.* 引用需要移除。taker.frt.* 仅支持文件被替换事件。
- 旧记录没有保存的文件解析属性保持为空，不重新解析已改名的文件；准备阶段命名失败的通知覆盖不在本次调整范围内。
- 历史通知和已冻结的通知数据保持原样，不回填。
